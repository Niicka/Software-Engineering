## 1. 문서 개요

### 1.1 목적
본 문서는 머니새니(Money Sani) 앱 시스템의 기능적·비기능적 요구사항을 정의한다. 개발자가 시스템을 올바르게 구현하고, 테스터가 검증 기준을 수립할 수 있도록 하는 것이 목적이다.

### 1.2 범위
- **대상 시스템**: 머니새니 모바일 앱 (iOS / Android)
- **대상 사용자**: 대학생, 사회초년생 (주요 타겟: MZ세대)
- **포함 범위**: 프론트엔드 앱, 백엔드 서버, AI 분석 모듈

### 1.3 정의 및 약어
| 용어 | 정의 |
|------|------|
| 사용자 | 머니새니 앱에 가입하여 서비스를 이용하는 일반 이용자 |
| 챌린지 | 특정 기간 내 절약 목표를 달성하는 미션형 과제 |
| 포인트 | 챌린지 성공 또는 절약 행동에 따라 적립되는 보상 단위 |
| 충동소비 | 계획 없이 급작스럽게 발생하는 고액 지출 |
| AI 추천 | 머신러닝 기반 개인화 절약 팁 및 대체 소비 제안 |

## 2. 전체 시스템 기술

### 2.1 시스템 개요
머니새니는 사용자의 소비 데이터를 수집·분석하여 절약 습관 형성을 돕는 모바일 앱이다. 소비 리포트, 예산 관리, 챌린지, AI 분석, 커뮤니티 기능을 통합 제공한다.

### 2.2 시스템 구성도
```
[모바일 앱 (React Native)]
        ↕ HTTPS / REST API
[백엔드 서버 (Node.js/Express)]
        ↕
[데이터베이스 (MySQL + Redis)]
        ↕
[AI 분석 서버 (Python/Flask)]
```

### 2.3 사용자 특성
| 구분 | 특성 |
|------|------|
| 주요 사용자 | 20~30대 대학생, 사회초년생 |
| 기술 친숙도 | 스마트폰 앱에 익숙, 금융 앱 경험 있음 |
| 주요 니즈 | 소비 통제, 절약 동기부여, 금융 습관 형성 |

## 3. 기능적 요구사항

### FR-01. 회원 관리

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-01-01 | 사용자는 이메일과 비밀번호로 회원가입을 할 수 있다. | 상 |
| FR-01-02 | 사용자는 소셜 로그인(카카오, 구글)으로 가입/로그인할 수 있다. | 중 |
| FR-01-03 | 사용자는 로그인 후 JWT 토큰 기반 인증을 통해 앱을 이용한다. | 상 |
| FR-01-04 | 사용자는 프로필(닉네임, 프로필 이미지)을 수정할 수 있다. | 하 |
| FR-01-05 | 사용자는 회원 탈퇴를 요청할 수 있으며, 탈퇴 시 개인 데이터는 삭제된다. | 중 |

---

### FR-02. 소비 리포트 및 분석

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-02-01 | 사용자는 소비 내역을 수동으로 등록할 수 있다. (금액, 카테고리, 메모, 날짜) | 상 |
| FR-02-02 | 시스템은 카테고리를 자동으로 분류한다. (식비, 쇼핑, 교통, 구독, 여가, 기타) | 상 |
| FR-02-03 | 사용자는 주간 소비 리포트를 조회할 수 있다. | 상 |
| FR-02-04 | 사용자는 월간 소비 리포트를 조회할 수 있다. | 상 |
| FR-02-05 | 시스템은 전월 대비 소비 증감률을 그래프로 표시한다. | 중 |
| FR-02-06 | 사용자는 특정 기간의 소비 내역을 검색/필터링할 수 있다. | 중 |
| FR-02-07 | 시스템은 카테고리별 소비 비중을 파이 차트로 시각화한다. | 중 |

**소비 카테고리 분류 기준**
```
식비      → 음식점, 배달앱, 카페, 편의점 등
쇼핑      → 온라인 쇼핑몰, 의류, 잡화 등
교통      → 대중교통, 택시, 주유 등
구독      → OTT, 음악, 앱 정기결제 등
여가      → 영화, 여행, 취미 등
기타      → 위 분류에 해당하지 않는 항목
```

### FR-03. 예산 설정 및 알림

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-03-01 | 사용자는 월 전체 예산을 설정할 수 있다. | 상 |
| FR-03-02 | 사용자는 카테고리별 예산을 별도로 설정할 수 있다. | 상 |
| FR-03-03 | 시스템은 예산 대비 현재 소비 달성률을 퍼센트와 게이지 바로 표시한다. | 상 |
| FR-03-04 | 소비가 예산의 80%에 도달하면 경고 푸시 알림을 발송한다. | 상 |
| FR-03-05 | 소비가 예산을 초과하면 초과 알림 푸시를 발송한다. | 상 |
| FR-03-06 | 사용자는 알림 수신 여부 및 알림 임계값을 설정할 수 있다. | 중 |
| FR-03-07 | 시스템은 매월 1일 예산이 초기화되며, 사용자에게 새 예산 설정 알림을 발송한다. | 중 |

### FR-04. 절약 챌린지

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-04-01 | 시스템은 기본 챌린지 목록을 제공한다. (예: "하루 커피값 아끼기", "배달 주 3회 줄이기") | 상 |
| FR-04-02 | 사용자는 원하는 챌린지에 참여 신청을 할 수 있다. | 상 |
| FR-04-03 | 사용자는 직접 커스텀 챌린지를 생성할 수 있다. (목표금액, 기간, 카테고리 설정) | 중 |
| FR-04-04 | 사용자는 친구를 초대하여 공동 챌린지에 참여할 수 있다. | 중 |
| FR-04-05 | 챌린지 성공 시 포인트 및 뱃지가 자동으로 지급된다. | 상 |
| FR-04-06 | 사용자는 현재 진행 중인 챌린지의 달성 현황을 실시간으로 확인할 수 있다. | 상 |
| FR-04-07 | 시스템은 챌린지 종료 24시간 전 리마인드 알림을 발송한다. | 중 |
| FR-04-08 | 챌린지 랭킹을 주간 단위로 집계하여 상위 10명을 공개한다. | 하 |

### FR-05. 보상 및 인센티브

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-05-01 | 챌린지 성공, 출석 체크, 절약 행동에 따라 포인트가 적립된다. | 상 |
| FR-05-02 | 사용자는 보유 포인트 내역과 잔액을 조회할 수 있다. | 상 |
| FR-05-03 | 사용자는 포인트를 기프티콘 또는 할인쿠폰으로 교환할 수 있다. | 상 |
| FR-05-04 | 절약 달성 횟수에 따라 레벨이 부여된다. (씨앗→새싹→나무→숲) | 중 |
| FR-05-05 | 사용자는 획득한 뱃지 목록을 마이페이지에서 확인할 수 있다. | 중 |

**포인트 적립 기준**
| 행동 | 적립 포인트 |
|------|-------------|
| 챌린지 성공 | 100 ~ 500P (난이도 비례) |
| 일일 출석 체크 | 10P |
| 소비 절약 달성 (예산 내 지출) | 50P |
| 커뮤니티 게시글 작성 | 5P |
| 첫 번째 챌린지 참여 | 30P (최초 1회) |

### FR-06. AI 충동소비 탐지

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-06-01 | 시스템은 사용자의 평균 소비 패턴과 크게 다른 지출을 충동소비로 탐지한다. | 상 |
| FR-06-02 | 충동소비 탐지 시, 해당 지출에 대한 알림과 함께 절약 팁을 제공한다. | 상 |
| FR-06-03 | 시스템은 소비 이력 기반으로 개인화 절약 팁을 주 1회 이상 제공한다. | 중 |
| FR-06-04 | 사용자는 AI 추천 절약 팁에 대해 "도움이 됐어요" / "별로예요" 피드백을 남길 수 있다. | 중 |
| FR-06-05 | 피드백 데이터를 학습에 반영하여 추천 정확도를 점진적으로 향상시킨다. | 하 |

**충동소비 탐지 기준 (예시)**
```python
# 충동소비 판별 기준 (예시 로직)
평균 일별 지출의 3배 이상 + 기존에 없던 카테고리 → 충동소비 의심
평균 주별 지출의 2배 이상 초과 → 과소비 경고
```

## 4. 비기능적 요구사항

### NFR-01. 성능

| ID | 요구사항 |
|----|----------|
| NFR-01-01 | API 응답 시간은 일반 요청 기준 95th percentile에서 1초 이내여야 한다. |
| NFR-01-02 | AI 분석 결과 응답 시간은 3초 이내여야 한다. |
| NFR-01-03 | 앱 콜드 스타트(첫 실행) 시간은 3초 이내여야 한다. |
| NFR-01-04 | 동시 접속자 100명 이상의 상황에서 성능 저하 없이 서비스를 제공해야 한다. |

### NFR-02. 보안

| ID | 요구사항 |
|----|----------|
| NFR-02-01 | 모든 통신은 HTTPS(TLS 1.2 이상)를 통해 암호화되어야 한다. |
| NFR-02-02 | 비밀번호는 bcrypt 알고리즘(salt rounds ≥ 10)으로 해싱하여 저장한다. |
| NFR-02-03 | JWT 액세스 토큰 유효기간은 1시간, 리프레시 토큰은 14일로 설정한다. |
| NFR-02-04 | 개인 금융 데이터는 AES-256으로 암호화하여 DB에 저장한다. |
| NFR-02-05 | 개인정보보호법에 따라 필요 최소한의 개인정보만 수집한다. |

### NFR-03. 사용성

| ID | 요구사항 |
|----|----------|
| NFR-03-01 | 신규 사용자가 회원가입 후 첫 소비 등록까지 5단계 이내에 완료할 수 있어야 한다. |
| NFR-03-02 | 주요 기능(소비 등록, 예산 확인, 챌린지 참여)은 앱 진입 후 2탭 이내로 접근 가능해야 한다. |
| NFR-03-03 | 컬러 대비는 WCAG 2.1 AA 기준(대비율 4.5:1 이상)을 준수한다. |

### NFR-04. 유지보수성

| ID | 요구사항 |
|----|----------|
| NFR-04-01 | 모든 소스코드는 GitHub에 버전 관리되며, 커밋 메시지 규칙을 준수한다. |
| NFR-04-02 | 핵심 비즈니스 로직(포인트 계산, 챌린지 판정)은 단위 테스트 커버리지 70% 이상을 달성한다. |
| NFR-04-03 | API는 RESTful 설계 원칙을 준수하여 확장성을 보장한다. |

### NFR-05. 가용성

| ID | 요구사항 |
|----|----------|
| NFR-05-01 | 서비스 가용성(Uptime)은 월 기준 99% 이상을 목표로 한다. |
| NFR-05-02 | 정기 점검 시 사용자에게 사전 공지 후 새벽 시간대(02:00~04:00)에 수행한다. |
